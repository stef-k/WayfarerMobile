Direct/manual guidance is network-free. Retained routes require exact current
account/server/authority/mode/profile/endpoints/ordered anchors and valid stored data.

session, Timeline or Trip state. No provider contact is part of preparation tests.

## Upgrade behavior

Install the later reviewed, production-signed APK over 1.2.0 without uninstalling or
clearing storage. Application ID remains `me.stefk.wayfarermobile`; display version
is `1.3.0`, code `4` (greater than the published APK's `3`). Device preservation is
still pending; an export is useful protection but does not back up all app-private
state. Downgrade safety across these schema changes is not established.

Released source uses schema 6; current initialization creates/adds mapped columns
before running migrations through schema 12:

| Schema | Change |
| --- | --- |
| 7 | Transactionally rebuilds DownloadedTrips retaining content/identity fields, normalizes old download states; drops TripTiles/TripDownloadStates and removes owned Trip raster files and obsolete raster preferences. Live cache and user content remain. |
| 8 | Adds OfflineSegments.WaypointsJson and HasCustomRoute; existing Geometry remains. |
| 9 | Deletes only cached_osrm_route preference, without interpreting its value. |
| 10–11 | Creates retained-route table/indexes and adds nullable ProviderMode for an existing schema-10 install. No retained route existed in released 1.2.0. |
| 12 | Deletes only last_transport_mode; no mode inference or user-content rewrite. |

A downloaded Trip continues to provide its Places, Segments and saved geometry offline.
Old bulk raster maps are intentionally removed. Only previously browsed live tiles
may be available offline; do not rely on complete regional map coverage.
Queue recovery suspension survives restart and requires explicit Resume and reconcile.
Timeline import does not recreate pending upload state or import into the backend.
See [tracking and recovery](../05-Location-Tracking.md) and
[Trips and offline use](../04-Trips-and-Offline.md).

## Draft device checklist (pending)

1. Upgrade over 1.2.0 without clearing data: verify login, settings, pending queue,
   Timeline, downloaded Trips, notes and saved geometry remain.
2. Tracking/sync: capture controlled points offline, restart, reconnect and verify
   delivery without loss/duplicates; exercise recovery export/resume deliberately.
3. Timeline: refresh/edit/delete and round-trip CSV with quoted multiline notes and
   GeoJSON, including an older export; verify local versus backend import boundaries.
4. Trips/offline maps: open a downloaded Trip offline, inspect intermediate Places
   and saved geometry; confirm intentional bulk-map removal and live-cache limits.
5. Navigation: saved and retained guidance, explicit fresh provider-native mode,
   cancellation and network-free Direct; verify HUD, Trip sheet and screen-on behavior.
6. Groups: verify peer visibility toggle and group updates with maintainer-controlled
   accounts; record backend observation status before a publication decision.
